# HyperSABMemory — Known Limitations

1. **Deterministic Verification vs. Open-Ended Prose Q&A**: `searchGrounded` verifies exact symbols, scoped JSON scalars, quoted substrings, explicit `Decision:`/`Decision-Source:` links, and direct TypeChecker test links. It intentionally abstains (`answerVerified: false`) rather than synthesizing speculative answers to conceptual architecture questions (which causes frozen `repository-task-eval.mjs` `supportedAnswerCoverage` to remain `0` on open-ended prompts).
2. **Static Test Attribution (`execution: "unverified"`)**: Test-to-implementation attribution inspects static TypeScript/ESM value-import bindings and direct/`it.each` call expressions (`Vitest` and `node:test`/`node:assert`). It never runs tests, always sets `execution: "unverified"`, and currently abstains safely (`0/9` positive links, `0` false links in Gate 5.5 across `headers-polyfill`, `js-yaml`, `fast-json-stringify`) on several idiomatic patterns: `export const` arrow functions (`P1`), directory barrel re-exports (`P2`), default export/import bindings (`P3`), `export class` constructor/rejection assertions (`P4`), single-assignment intra-test variable bridges (`P5`), dynamic `for...of` test titles (`P6`), `.mjs` test files calling TS sources directly, and CommonJS `require()` / Mocha patterns without ES TypeChecker imports.
3. **Logical vs. Physical Forgetting**: `forget` and supersede exclude forgotten/superseded entries from all active surfaces (`Memory.md`, `memory-log`, `context-block`, search/query tools, `task_context`), while retaining tombstone/audit metadata inside `.hypersabmemory/memory_store.json`, `.bak`, and prior Git commits for provenance and anti-resurrection guards.
4. **Native SQLite Binary & Filesystem Environment**: Requires Node `>= 20` and a working `better-sqlite3@12.9.0` prebuild or native C++ build toolchain per OS/CPU ABI. Unprivileged Windows environments without Developer Mode reject file symlinks (`EPERM`), though Windows directory junctions (`PASS` in Gate 5.5) and POSIX symlinks are supported and tested.
5. **Cold TypeScript Latency Scaling**: Cold first-call TypeChecker program construction scales with TypeScript file count (`<= 500 ms` budget covers medium OSS repos, not multi-thousand-file monorepos).
6. **Non-Runtime Eval Artifacts in Current Packaging**: `package.json` `files` excludes large evaluation/baseline fixture binaries while keeping baseline/smoke scripts intact; full tarball trimming is slated cleanly for future cleanup.
7. **Strict JSON Required for Existing MCP Configuration Merge**: `setup` and `connect` validate `.cursor/mcp.json`, `.mcp.json`, and `.vscode/mcp.json` as strict JSON objects (leading UTF-8 BOM supported) and reject symlinked paths or JSONC comments/trailing commas fail-closed with exit code `1` rather than overwriting malformed user configurations.
